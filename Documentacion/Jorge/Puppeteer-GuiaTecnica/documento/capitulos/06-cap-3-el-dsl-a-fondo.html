3 · El DSL a fondo

Todo el lenguaje con el que le hablas a un actor: literales, expresiones, print, ámbito, @Now y upgrade.

El DSL de Puppeteer es diminuto a propósito. No es un lenguaje de propósito general: su trabajo es orquestar tu dominio en C# —construir objetos y llamar sus verbos— y dejar el hecho anotado en el diario. En este capítulo lo recorremos completo. Es corto: en una sentada lo tienes. Todos los fragmentos con salida provienen de ejemplos que compilan y corren (Anexo A).

3.1 · El cuerpo de un script

Un script es una secuencia de sentencias terminadas en ;. Las cadenas van entre comillas simples. Puedes agrupar varias sentencias como una unidad con un bloque { … }, y comentar con // o /* … */.

DSLsaldo = 0;                 // asignacion; termina en ;
saldo = saldo + 100;       /* los comentarios no afectan nada */
nota = 'primer abono';     // texto entre comillas simples
{ a = 1; b = 2; }          // un bloque agrupa sentencias

La aritmética promueve al tipo más ancho: decimal > double > long > int. Así, mezclar un entero con un decimal da decimal, y sumar dos enteros que se salen del rango de int no desborda si usas long:

DSL{ x = 1 * 2.25m; y = 2000000000L + 2000000000; print x 'x', y 'y'; }
Salida real{"x":2.25,"y":4000000000}
✎ Nota del diseñador

Hay una sola excepción a la promoción: int / int da double, nunca división entera truncada. Es una decisión deliberada — el resultado “natural” de dividir dos enteros casi nunca es el cociente entero, y esconder esa sorpresa evita errores silenciosos.

3.3 · Expresiones y operadores

Tienes aritmética (+ - * / y el unario -), el operador ternario y concatenación de texto:

DSLx = a * 2 + -b;                 // aritmetica y unario
etiqueta = n > 0 ? 'positivo' : 'no positivo';   // ternario
saludo = 'total = ' + 5;         // concatenacion: texto a la IZQUIERDA
✕ No hagas

No pongas el número a la izquierda de una concatenación (5 + 'x'). Ahí + es ambiguo entre sumar y concatenar, y el comportamiento puede divergir. Pon siempre el texto a la izquierda: 'x' + 5.

Así se ve en el bingo real: para darle una identidad única a cada aviso, se concatena texto con valores — nota que la expresión arranca con texto:

DSL · realonce 'bolita-' + @ronda + '-' + @numero;

3.4 · print a fondo

Ya usaste print <expr> '<etiqueta>';. Además, una sola sentencia puede emitir varios valores separados por coma, y la etiqueta se puede escribir con o sin comillas (las comillas solo hacen falta si la etiqueta lleva espacios):

DSLprint total * 2 grandTotal, contador 'live count';

Un detalle útil: al imprimir un valor de enumeración, print emite el nombre del miembro como texto, no su número — igual en JSON y en el resto de formatos. Es lo que hace legible el resultado sin que tengas que traducir códigos.

Así lo usa el bingo real. Para leer una lista, un foreach imprime cada elemento con la misma etiqueta; y para traerse varios campos de una ronda en una sola ida al actor, se agrupan varios print en un bloque:

DSL · real// una lista: cada numero disponible sale bajo la etiqueta 'c'
foreach (n in festival.NumbersUpForSale()) { print n 'c'; }

// varios campos de una ronda, en una sola query
{ print festival.RoundAt(1).Playing f;
  print festival.RoundAt(1).HowItStands s;
  print festival.RoundAt(1).PromiseCount q; }

3.5 · Estado raíz vs. variables locales

Dónde colocas una asignación decide qué es. Esta es la regla completa:

Dónde asignasQué es¿Persiste / se journaliza?
Identificador suelto en el nivel superior del comandoglobal = estado raíz del actorSí, entre comandos
Dentro de un bloque { } (o cuerpo de if / foreach)localNo — muere con el bloque
Dentro de un cuerpo upgrade { }global (excepción; ver 3.7)Sí
 Tabla 8. La regla de ámbito: el lugar de la asignación decide su alcance.

Veámoslo: total es raíz (persiste); doble vive solo dentro de su bloque:

DSLtotal = 5;                              // comando 1: raiz
{ doble = total * 2; print doble 'doble'; }   // query: 'doble' es local
print total 'total';                     // query: 'total' sigue ahi
Salida real{"doble":10}
{"total":5}
✓ Haz

Encierra las variables de trabajo en un bloque { } para que sean locales y no ensucien el estado raíz. Promueve a global (nivel superior) solo lo que debe persistir. El estado raíz es memoria que se journaliza: manténlo mínimo e intencional.

3.6 · @Now: el tiempo determinista

Dentro de un script nunca lees el reloj del sistema. Usas @Now, un DateTime real que el framework inyecta y fija una sola vez por invocación. No hay que declararlo:

DSLprint @Now.Year 'anio';
agenda.Programar(@Now.AddDays(1));   // es un DateTime real: opera con sus miembros
Salida real{"anio":2026}

Como vimos en el Capítulo 1, esto es lo que hace posible el replay: en vivo, @Now es el reloj real y queda anotado en el diario; al reproducir, se reinyecta ese mismo instante. La hora original y cada reproducción coinciden, siempre.

✎ Nota del diseñador

Todos los @Now de una misma invocación valen exactamente lo mismo: se muestrea una vez, en el borde de la invocación. Y para ActorV2, @Now es el único “ahora” correcto — el mecanismo antiguo ExecutionContext.Current.Now lanza si lo usas en V2.

3.7 · upgrade: inicializar una sola vez

El bloque upgrade('<nombre>') { … } corre exactamente una vez por actor, identificado por su nombre. Es la herramienta para sembrar o migrar estado que no debe re-ejecutarse. A diferencia de un bloque normal, sus asignaciones de nivel superior sí quedan como estado raíz —esa es justamente su razón de ser—:

DSLupgrade('seed') { saldo = 100; }
Salida real{"saldo":100}

Re-emitir el mismo upgrade('seed') no hace nada: ya se aplicó. Así, la misma llamada sirve para nacer y para rehidratar — es exactamente el patrón que viste en el bingo real, donde upgrade('festival') crea la velada la primera vez y la reconstruye en cada arranque posterior.

✕ No hagas

No edites el cuerpo de un upgrade ya aplicado: el framework lo rechaza (los diarios viejos deben rehidratar su versión original). Para cambiar algo, publica un nombre nuevo — upgrade('seed_v2') { … } —. Cada upgrade es una “liberación” con nombre, y su historia queda auditable en el diario.

✎ Nota del diseñador

upgrade solo es válido en comandos: en una query o en una guarda lanza al analizar, porque crea estado que se journaliza. Y si su cuerpo falla, la marca de “aplicado” no se pone y nada persiste: un cuerpo corregido corre en el siguiente intento. La inicialización, así, es segura ante fallos.

Lo que aprendiste

  • El DSL orquesta el dominio: sentencias con ;, texto con comillas simples, bloques con { }.
  • Literales tipados y promoción decimal > double > long > int; concatenación con el texto a la izquierda.
  • print emite uno o varios valores etiquetados; los enums salen por su nombre.
  • La regla de ámbito: nivel superior = estado raíz que persiste; bloque = local efímero.
  • @Now da tiempo determinista; upgrade inicializa una sola vez y evoluciona por nombres nuevos.
